## Goal

M6 turns the M2/M3 core into a working `task` mode. A task run gets a **workspace** (a root plus allowed paths that become `RunCapabilities.fsRoots`, path-normalized and symlink-resolved so nothing escapes the root), the built-in **`workspace` extension** (`workspace__list/read/search/patch/write/create/delete/shell`, with `patch` requiring exactly one match and `shell` running argv without a shell), **checkpoints** written to the journal before every `write`+ action, **pause and resume** backed by the transcript (the `:pause`/`:resume` routes M4 shipped without backing), **subtasks** (`task__spawn`, depth ≤ 2, rights `parent.narrow(requested)`, budget reserved from the parent), **budgets** (`max_steps` 200 / `max_tokens` / `max_wall_time` 8 h for tasks, plus a global daily spending limit), **transcripts** (the `transcripts` box of section 15.6, resolving Q15, exposed as `GET /v1/runs/{id}/transcript`), and **context compaction** (section 15.7, T18: goals and open items preserved). The CLI gains the `runs` command group (`ls | show | cancel | pause | resume | checkpoints | restore`). LSP and MCP stay out (M7/M8).

## Acceptance criteria

- [ ] T18 spike lands first: a context-compaction spike with a test that preserves goals and open items, and the compaction design recorded (verified by the Step 1 spike test and `docs/spikes/`).
- [ ] A `task` run resolves a workspace root and allowed paths into `RunCapabilities.fsRoots`; a path that leaves the root through `..` or a symlink is rejected (verified by `runtime/core/test/domain/workspace_test.dart`).
- [ ] The `workspace` extension registers `workspace__list/read/search/patch/write/create/delete/shell`; `patch` requires exactly one match, `create` never overwrites, `shell` runs argv without a shell and rejects metacharacters, and only the allowlist runs (verified by `extensions/workspace/test`).
- [ ] The `official` build names `alteri_one_ext_workspace` and produces a runnable binary; `minimal` still names no extension (verified by `runtime/bin/test/build_smoke_test.dart`, updated).
- [ ] The `transcripts` box (§15.6) is implemented with an explicit owner and write protocol (Q15), and `GET /v1/runs/{id}/transcript` (scope `read.io`) returns the run's messages (verified by `runtime/core/test/infrastructure/journal` and `runtime/core/test/infrastructure/server/resources_test.dart`).
- [ ] A checkpoint is written and flushed before every `write`+ tool call, records file hashes + artifact references + transcript position, and `alterione runs restore <id> <cp>` / `POST /v1/runs/{id}/checkpoints/{cid}:restore` rolls back (verified by `runtime/core/test/application/checkpoint_test.dart`).
- [ ] Pause stops new calls at the next step boundary; resume rebuilds the context from the transcript (not process memory) and reproduces the same context; `kill -9` then `resume` continues (verified by `runtime/core/test/application/run_service_test.dart` and a recovery test).
- [ ] `task__spawn` narrows rights to `parent.narrow(requested)`, reserves and subtracts the subtask budget from the parent, caps depth at 2, and a subtask's tainted result taints the parent (verified by `runtime/core/test/application/subtask_test.dart`).
- [ ] Budgets: `max_duration` and the per-reply `max_output_tokens` cap are enforced by the loop; `max_tokens` (cumulative) and the daily spending limit are enforced once `Turn` reports usage (verified by `runtime/core/test/application/agent_loop_test.dart` and a daily-ledger test).
- [ ] The CLI `alterione runs ls | show | cancel | pause | resume | checkpoints | restore` works against a fake client, with `--json` and exit codes 0/2/3/4/5 (verified by `runtime/cli/test`).
- [ ] e2e "fix a failing test" on a small Dart project: a task run edits a file through `workspace__patch`, a checkpoint is created, the run pauses and resumes, and the final report lists changed files from the journal (verified by `e2e/test/alteri_one_m6_e2e_test.dart`).
- [ ] `docs/spec/` is updated for the new behavior, the ADRs are filed, `docs_check` exits 0, and the per-package ci commands are green.

### Part 1 — Spike (critical path)

- [ ] Step 1: Spike T18 context compaction and record the design. Add a spike under `docs/spikes/m6-context-compaction.md` (and a `runtime/core/test/spike/` test) that summarizes a long synthetic transcript through a fake `LlmPort`, asserts the summary preserves the stated goals and open items, and that the summarized message range keeps its untrusted labels (section 15.7). Record the chosen trigger (approach the model window), the summary event shape (references the summarized range), and the label-propagation rule. If quality is not verifiable with a fake, record the fallback (a deterministic extractive summary that preserves goals/open items verbatim) here. Tests: the spike test. This step gates Step 13's compaction wiring. **(parallelizable with Step 2 once the design is recorded)**

### Part 2 — Domain and state

- [ ] Step 2: Add the task-mode domain and configuration surface in `runtime/core`. Add a `Workspace` value (`root` + `allowedPaths`) and a `TaskConfig` (`workspace`, `autoResume`, `shellAllowlist`) in `runtime/core/lib/src/domain/`; extend `Profile` (`lib/src/domain/profile.dart`) and the schemantic `$ProfileConfig`/`$BudgetConfig` (`lib/src/config/profile_schema.dart`, regenerate `.g.dart`) with `workspace`, `auto_resume`, and `shell_allowlist`, and map them in `application/config/profile_loader.dart` (extend `_profileKeys`, reject unknown keys, semantic checks). Add the default task budget (`max_steps` 200, `max_wall_time` 8 h) as a `Budget.task()` factory in `lib/src/domain/budget.dart` (keep `Budget.standard()` for chat). Do not change `PolicyGate`, taint, or the loop here. Tests: `runtime/core/test/domain/workspace_test.dart` (normalization, `..` and symlink rejection via a pure path resolver) and `runtime/core/test/application/config/profile_loader_test.dart` (new keys, unknown-key rejection, task budget defaults). **(parallelizable with Step 1)**

### Part 3 — Storage and transcripts (Q15)

- [ ] Step 3: Resolve Q15 and implement the transcript/artifact/checkpoint stores in `runtime/core`. Decide and record (ADR-0029) that a new application-layer `TranscriptRecorder` (not `JournalingLlm`, not the journal port) owns the transcript: the agent loop calls it after appending an assistant turn and after a tool batch. Add a `TranscriptPort` (`lib/src/domain/ports/transcript_port.dart`) and a `HiveTranscriptStore` over a `transcripts` `LazyBox<String>` keyed `{runId}:{seq:012}` (section 15.6), an `artifacts` directory addressed by `{sha256}` (immutable, dedup, quota from config, default 2 GB, files over the 10 MB threshold recorded by hash + `not restorable`), and a `checkpoints` `Box<String>` keyed `cp:{runId}:{cpId}`. Extend `JournalPort`/`HiveJournal` (`lib/src/domain/ports/journal_port.dart`, `lib/src/infrastructure/journal/hive_journal.dart`) with transcript/checkpoint append and read methods, and add `lib/src/domain/transcript.dart` and `lib/src/domain/checkpoint.dart`. Wire the recorder into `application/agent/agent_loop.dart` and `application/run_service.dart`. Tests: `runtime/core/test/infrastructure/journal/transcript_store_test.dart` (round-trip, artifact dedup, quota, oversize marker) and a `run_service` transcript test. **(parallelizable with Step 2)**

### Part 4 — Workspace extension (host-call channel)

- [ ] Step 4: Add the `GET /v1/runs/{id}/transcript` route (scope `read.io`) in `runtime/core`. Extend `RunResourcePort` (`lib/src/infrastructure/server/routes.dart`) with `getTranscript(id)` and add the route in `lib/src/infrastructure/server/http_api.dart` (scope `read.io`, 404 when the port is absent), backed by an adapter in `lib/src/infrastructure/daemon/run_registry.dart` and wired in `daemon.dart`. - [ ] Step 5: Add the extension→host call channel. In `packages/sdk` add a `HostClient` and expose it on `ExtensionContext` (e.g. `ctx.host`), and in `runtime/core` handle the new frames in `infrastructure/extension/isolate_extension_transport.dart` and the built-in path `application/agent/built_in_extension_context.dart`, routing each call through `HostApi`. - [ ] Step 6: Extend `HostApi` with the file-system operations the workspace needs in `runtime/core/lib/src/application/host_api.dart` — `list/read/search/patch/write/create/delete/shell` under `host.fs:<path>`, with a `HostFileSystem` whose production impl (`lib/src/infrastructure/daemon/`) normalizes and symlink-resolves every path against the run's `fsRoots`, rejects escapes, enforces the artifact size threshold, and runs `shell` as argv (no `sh -c`, metacharacter rejection, allowlist → `write`, else `destructive`) with `timeoutMs`. ### Part 5 — Subtasks

- [ ] Step 9: Implement `task__spawn` as a built-in core tool (not an extension) in `runtime/core/lib/src/application/agent/`. The model requests a subtask with a goal and a tool set; rights are `parent.narrow(requested)` (section 8.2), the subtask budget is reserved from and subtracted from the parent's, depth is capped at 2, a subtask cannot approve its own actions (the request goes to the owner through the parent's channel, marked as a subtask), and a subtask's tainted result taints the parent. Register it in the tool registry (`agent_defaults.dart`/`extension_tool_registry.dart`) only for `task` runs. Tests: `runtime/core/test/application/subtask_test.dart` (rights narrowing, budget reservation/subtraction, depth cap, taint propagation, approval routing). Depends on Step 2. **(parallelizable with Steps 10/12)**

### Part 6 — Budgets (Q11)

- [ ] Step 10: Enforce the usage-free budgets in the loop (`runtime/core/lib/src/application/agent/agent_loop.dart`). Track the run start time and check `max_duration` before each step; keep passing `max_output_tokens` as the per-reply cap; on exhaustion return a `budgetExceeded` outcome (extend `run_result.dart` if the wall-clock case needs its own variant). Add the `max_steps` 200 default for tasks via `Budget.task()` (Step 2). Tests: `runtime/core/test/application/agent_loop_test.dart` (duration exceeded, output cap, step cap). **(parallelizable with Step 9)**
- [ ] Step 11: Enforce the usage-based budgets. Add an additive `usage` (input/output tokens) to `Turn` in `packages/provider_api/lib/src/messages.dart` (minor bump + changelog), parse it in `providers/llama_cpp/lib/src/llama_cpp_llm.dart`, and in `runtime/core` accumulate tokens per run and enforce `max_tokens`, plus a global daily spending limit read from daemon config (`lib/src/infrastructure/daemon/daemon_config.dart` + a `daily` block in `alterione.yaml`). Exceeding moves the run to `budgetExceeded`. Tests: `runtime/core/test/application/agent_loop_test.dart` (token budget) and a daily-ledger test. Depends on Step 10.

### Part 7 — Pause, resume, and checkpoints

- [ ] Step 12: Back the `:pause`/`:resume` routes in `runtime/core`. Add a pause point to the loop (check `paused`/`cancelled` before each step, section 29.5): `RunRegistry.pauseRun` (`lib/src/infrastructure/daemon/run_registry.dart`) drives the run to `paused` (the current call finishes or is cancelled on timeout) instead of returning a conflict; `resumeRun` rebuilds the context from the transcript (Step 3, not process memory) and continues from the last completed step, with the determinism check that replaying the transcript yields the same context. Wire the pause/resume events through `run_service.dart`/`run_bloc.dart`. Tests: `runtime/core/test/infrastructure/daemon/run_registry_test.dart` (pause/resume) and `runtime/core/test/application/run_service_test.dart` (replay determinism). Depends on Steps 3, 10.
- [ ] Step 13: Create checkpoints before every `write`+ action and expose restore. In `runtime/core/lib/src/application/agent/agent_loop.dart` (or a `CheckpointRecorder` beside the transcript recorder), before a tool call whose effective risk is `write` or higher, write and flush a checkpoint (files, hashes, artifact refs, transcript position) to the `checkpoints` box (Step 3); the model cannot start a rollback. Add `restoreRun(id, checkpointId)` to `RunResourcePort`/`RunRegistry` and the `POST /v1/runs/{id}/checkpoints/{cid}:restore` route (scope `run`, requires confirmation) plus `GET /v1/runs/{id}/checkpoints`. The final report's changed-file list is built from the journal, not the model's words. Tests: `runtime/core/test/application/checkpoint_test.dart` (checkpoint before write, restore, oversize not-restorable) and `resources_test.dart` (checkpoint routes). Depends on Steps 3, 6, 12. **(parallelizable with Step 14 once Step 13 lands)**
