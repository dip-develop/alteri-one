## Goal

M5 builds the extension mechanism end to end. `packages/contracts` gains `observes:` on the manifest, a promoted `StateTopic`, a schemantic-generated manifest JSON Schema, and a shared canonical-JSON function; `packages/sdk` gains the author API (`AlteriOneExtension`, `ExtensionContext`, `runExtension`). `runtime/core` gains the `ExtensionTransport` port, a host-side `HostApi` with per-call permission checks (effective set = `manifest.permissions ∩ extensions/<id>.yaml`), the `IsolateExtensionTransport` implementation (handshake, newline-delimited JSON framing, `StatePublisher` subscription with pause/resume backpressure), the `ExtensionsBloc` loading/draining effects, the owner-approval loader, and the `:load`/`:unload` admin routes. `tools/signing` becomes a real Ed25519 signer/keygen over canonical JSON with a `0600` key file, and `docs/security/` records the signing-key policy. `runtime/bin` gains `alterione build` (validate → generate → resolve → `dart build cli` → compile+sign loaded extensions) producing runnable `minimal` and `official` binaries, with `lsp`/`mcp` commented out of `official` (M7/M8 scaffolds). The `weather` reference extension runs identically in built-in and loaded modes (e2e parity). `memory_hive` becomes a real `MemoryPort` backend selected through a core `MemoryBackendRegistry`, `skill.load` serves approved `SKILL.md` bodies, and state observation delivers snapshot + events with `resync_required` on overflow (T15 per-topic limits). `doctor` extension/distribution checks are un-skipped. LSP and MCP are out of M5.

## Steps

One tracking issue is filed before implementation; its body is the checklist below. Steps are ordered by the critical path: the ADR-0007 spike comes first because a failed load changes the transport design; contracts land before the SDK and transport; the SDK before the transport implementation and the reference extension; signing and `alterione build` before the loaded-mode e2e parity; observation, `memory_hive`, and `skill.load` build on the transport and SDK. Per `docs/plan/README.md`, the list is not rewritten after the fact — if the plan changes, add a new item marked "added" and keep the old one. `melos` is broken in this container (see M3.md/M4.md), so every step uses the per-package commands in Acceptance commands. Steps marked **(parallelizable)** can run alongside another step once their stated dependency has landed.

Risks and dependencies: Step 1 gates the transport shape (failure → separate-process fallback, new ADR); the SDK (Step 3) and signing (Step 6) both depend on the contracts additions (Step 2); the loaded-mode e2e parity (Step 10) depends on both signing (Step 6) and `alterione build` (Step 8); T10/T11/T15/T19 are [VERIFY] spikes that may force a fallback (custom `SKILL.md` parser, `dart compile exe`, a `0600` key file, per-topic limit tuning) — each fallback is recorded in Open checks and, where it changes a decision, in an ADR.

### Part 3 — Transport, HostApi, permissions, bloc (core)

- [ ] Step 4: Add the `ExtensionTransport` port in `runtime/core/lib/src/domain/ports/extension_transport.dart` — an `abstract interface class ExtensionTransport` with `spawn(uri, handshakeTimeout) -> LoadedExtension`, where `LoadedExtension` exposes `manifest`, `call(tool, input, cancel)`, `drain(timeout)`, `kill()`, and `events`. Pure domain, no `dart:io`. Export from the core library. Tests: a fake transport in `runtime/core/test` (no real isolate yet). This is the seam the bloc and composition depend on.
- [ ] Step 5: Add the host-side `HostApi` and per-call permission checks in `runtime/core/lib/src/application/host_api.dart` — operations `secret(name)` → `host.secret:name`, `readFile`/`writeFile` → `host.fs:path`, `memoryStore` → `host.memory.write`, `memoryRecall` → `host.memory.read`, `netGet` → `net:host` (exact, no wildcard); the effective permission set is `manifest.permissions ∩ extensions/<id>.yaml`; a denial returns `call.error` `forbidden` and writes a denied-call journal record; secrets never enter the model context. Depends on Step 4 (port) and Step 2 (contracts). Tests: `runtime/core/test/application/host_api_test.dart` (each op allowed/denied, denied call journalled, `net:` exact-host).
- [x] Step 7: Implement `IsolateExtensionTransport` in `runtime/core/lib/src/infrastructure/extension/isolate_extension_transport.dart` — `Isolate.spawnUri` with `onExit`/`errorsAreFatal`, the newline-delimited `{v:1,kind:...}` framing, the `hello` handshake (register routes only after `hello`, `handshakeTimeout` → `kill` + `handshake-timeout`, reject unknown `kind`), reuse of `AgentEvent.fromJson` for observation, and a per-extension `StatePublisher` subscription with pause/resume backpressure (mirroring `infrastructure/server/sse.dart`). Depends on Steps 1, 2, 3, 4, 5. Tests: `runtime/core/test/infrastructure/extension/isolate_extension_transport_test.dart` (handshake, timeout, framing, unknown kind, backpressure).
- [x] Step 7b (added): Model the extension message frames as schemantic types in `packages/contracts/lib/src/frames.dart` — `HelloFrame`/`CallFrame`/`CallResultFrame`/`CallErrorFrame`/`CancelFrame`/`EventFrame` with generated `toJson`/`fromJson`, and refactor the SDK (`run_extension.dart`, `runtime.dart`) and the host transport (Step 7) to construct/parse them instead of hand-rolled maps. The `hello` `SendPort` stays a native field outside the model; the wire bytes are unchanged, so this supersedes the Step 7 native-`Map` framing. Recorded in [ADR-0022](../adr/0022-extension-message-frames-schemantic-models.md). Tests: contracts golden frame tests, plus the unchanged SDK and transport behavior tests.
- [x] Step 8: Wire the `ExtensionsBloc` loading/draining effects and the real tool registry in `runtime/core` — implement the `loading → draining → stopped` transitions in `lib/src/application/extensions_bloc.dart` over the transport, replace `EmptyToolRegistry` (`lib/src/application/agent/agent_defaults.dart`) with a registry backed by loaded extensions (names `{extId}__{name}`, duplicate rejected), and register the new singletons in `lib/src/di/core_module.dart`.
