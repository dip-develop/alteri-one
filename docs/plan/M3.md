# Milestone M3: llama.cpp provider via LlamaPulse

- Status: Done
- Specification: `docs/spec/providers.md` (section 12), `docs/spec/domain.md` (section 8.5), `docs/spec/contracts.md` (section 10), `docs/spec/architecture.md` (sections 4 and 6)
- ADR: [0018](../adr/0018-llm-provider-contract-and-llamapulse-adapter.md) (superseded in part by [0019](../adr/0019-llama-cpp-http-only-adapter.md), the HTTP-only adapter) and [0020](../adr/0020-m3-part-2-llamacpp-conformance-acceptance.md) (part-2 acceptance evidence)
- Tracking issue: [#64](https://github.com/dip-develop/alteri-one/issues/64)

## Goal

A `providers/llama_cpp` provider that talks to **LlamaPulse**, an OpenAI-compatible `llama-server` at `http://127.0.0.1:8080/v1`. Part 1 (this PR) is the contract/DI groundwork; part 2 (a follow-up PR) is the provider, the conformance suite, and the remaining docs.

## Acceptance criteria

- [x] `alteri_one_provider_api` declares the model-call vocabulary and `LlmPort`; `alteri_one_core` re-exports them through shims, so every existing import path compiles unchanged (verified by `dart analyze` in `runtime/core`).
- [x] `registerProviders` is all-or-nothing on a duplicate `kind` and `registerLlmPort` refuses a second port; `RunService` resolves after both (verified by `flutter test --no-pub` in `runtime/core`; CI is the authoritative run).
- [x] `providers/llama_cpp` implements `ModelProvider` (options, base-URL normalization, errors, `probe`) and a single `LlmPort` over `package:http` (HTTP-only, ADR-0019; verified by `flutter test --no-pub` in `providers/llama_cpp`; CI is the authoritative run).
- [x] `alteri_one_testkit` ships conformance scenarios 1–6 and the core scenario 7; a provider that declares `nativeTools: true` without passing scenarios 1–4 fails the suite (scenarios 1–6 in `runProviderConformance`, scenario 7 in `runtime/core/test`; verified by `flutter test` in `packages/testkit`, `providers/llama_cpp`, and `runtime/core`; CI is the authoritative run).
- [x] Docs: ADR-0018, `domain.md` 8.5, `providers.md` 12.3, `open-questions.md` Q19–Q23, and the `provider_api` changelog with the 0.x breaking note. (Step 3; the part-2 doc updates landed in this PR via [ADR-0020](../adr/0020-m3-part-2-llamacpp-conformance-acceptance.md), with the real-`llama-server` confirmation still a pending release gate.)

## Steps

- [x] Step 1: move the model-call vocabulary and `LlmPort` into `alteri_one_provider_api` (messages, port, `ModelProvider`, `LlmCapabilities`, `LlmUnavailable`), bump to 0.2.0, and keep `runtime/core` compiling through re-export shims. Migrate every `complete(...)` call site from `budget:` to `maxOutputTokens:`. Verified with `dart analyze` in `runtime/core`; tests run with `flutter test --no-pub` in `runtime/core` (CI is the authoritative run).
- [x] Step 2: core DI — `ProviderRegistry` (lookup by `kind`, reject duplicates) as a lazy singleton, plus `registerProviders` (all-or-nothing) and `registerLlmPort` (guarded) in `runtime/core/lib/src/di/injection.dart`.
- [x] Step 3: ADR-0018 and the spec amendment (domain.md 8.5, providers.md 12.3, open questions Q19–Q23).
- [x] Step 4 (part 2): `providers/llama_cpp` — options, base-URL normalization, errors, `ModelProvider`, `probe`.
- [x] Step 5 (part 2): `providers/llama_cpp` — `LlmPort` over `package:http`, the only adapter (HTTP-only; ADR-0019 supersedes the `genkit_openai` path of ADR-0018 decision 3).
- [x] Step 6 (part 2): `alteri_one_testkit` conformance scenarios 1–6 plus core scenario 7. Scenarios 1–6 run against a fake LlamaPulse server in every PR; the real-`llama-server` run is tagged `llamapulse`, skipped by default, and pending a local LlamaPulse (see `docs/spikes/m3-llamapulse-conformance.md`).
- [x] Step 7 (part 2): docs — ADR-0020 acceptance evidence, `providers.md` 12.3, real-`llama-server` confirmation (pending release gate, see `docs/spikes/m3-llamapulse-conformance.md`).
