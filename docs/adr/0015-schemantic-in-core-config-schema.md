# 0015. Schemantic is allowed in `runtime/core`

- Status: Accepted
- Date: 2026-11-19

## Context

Invariant 8 of `AGENTS.md` requires configuration to be YAML with a JSON Schema generated by schemantic, and section 6 of `docs/spec/architecture.md` listed `schemantic` as a dependency of `packages/contracts` only. The profile configuration (section 14 of `docs/spec/prompts-config.md`) is a `runtime/core` concern: the loader lives in `runtime/core/lib/src/application/config/`, and the profile is a domain value of the core. Generating its JSON Schema therefore needs `schemantic` in `runtime/core` itself, not just in `contracts`.

The alternative was to define the profile schema in `packages/contracts` and import it from the core. That would make a private configuration shape part of the published contract between extensions and the host, which section 10 of `docs/spec/contracts.md` does not ask for.

## Decision

`runtime/core` may depend on `schemantic`. The profile JSON Schema lives in `runtime/core/lib/src/config/profile_schema.dart` and is generated into `profile_schema.g.dart`, which is committed. The schema class describes the shape only: `risk_rules` and `tool_risks` stay string maps, and the loader owns the token validation against `Risk`, `Decision`, and `MemoryRights`.

A profile can only raise a tool's risk, never lower it: the schema and the loader accept a configured risk, and `Profile.validateToolRisks` rejects a profile that tries to lower the risk a tool declares. The effective risk stays computed by `effectiveRisk` at the loop seam.

Layer merging (defaults → `alterione.yaml` → environment → CLI) and path resolution (section 18.3) are deferred to M4 and to open question Q10. This ADR only admits the dependency and fixes where the schema lives.

## Alternatives

- Define the schema in `packages/contracts` and import it into the core: rejected; a private configuration shape would become part of the published contract, and `contracts` would gain a dependency on a configuration format it does not own.
- Write the JSON Schema by hand in `runtime/core`: rejected; invariant 8 requires a generated schema, and a hand-written schema drifts from the loader.
- Model `risk_rules` and `tool_risks` as enums in the schema: rejected; the loader must produce `ConfigurationException` messages that name the offending key, and keeping the tokens as strings leaves the token validation in one place.

## Consequences

- `runtime/core` gains one dependency, `schemantic` 1.0.0, and one dev dependency, `schemantic_builder`.
- `tools/arch_check` allows `schemantic` for `core` only, with a pointer to this ADR.
- The generated schema is committed and checked by `tools/codegen_check`.
- The profile schema is not published; extensions never see it.
