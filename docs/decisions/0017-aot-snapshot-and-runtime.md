# ADR-0017: The release is `alterione.aot` on a pinned `bin/dartrantime`

**Status:** Accepted
**Date:** 2026-09-29
**Affects:** `docs/architecture/build-and-release.md`,
`docs/architecture/install-and-update.md`, `_artifacts.yml`, the release gates

## Context

The release path before this record was `dart build cli` plus `dart install`: one
self-contained native executable per platform, with the Dart runtime linked inside it.
That is a good artifact. It has one property this project now wants to be able to
change, and one it wants to keep.

The property it wants to change: the executable and the runtime it was built against are
welded together. The Dart AOT snapshot format is **not** forward compatible across minor
versions — a snapshot built by 3.13 runs on a 3.13 runtime and on no other. Shipping the
runtime inside the executable means a user who needs a different runtime has to replace
the whole product, and it means the install footprint is dominated by a toolchain the
user may already have and is forbidden from reusing.

The property it wants to keep: no JIT, no runtime code loading, no `eval`, no
`Isolate.spawnUri` shortcut. ADR-0003 and ADR-0015 both depend on that.

There is a second, sharper constraint here. `dart compile aot-snapshot` does **not** run
build hooks: a dependency with `native_assets`, Code Assets or a build hook is silently
omitted or fails. The pre-split specification treated that as a reason to forbid
`dart compile` entirely. That was correct for the path it was describing and wrong as a
general rule — it forbade the tool rather than constraining the dependency closure.

## Decision

The installed product is **an AOT snapshot plus a separately downloaded, digest-verified
runtime**, and the two are version-checked against each other before anything executes.

```text
~/.alterione/                        # $ALTERIONE_HOME
├── alterione                        # launcher, executable, add this directory to PATH
├── alterione-update                 # update
├── install.sh | install.ps1 | install.cmd
├── alterione.aot                    # the compiled release
├── alterione.yaml                   # declared extensions, runtime and API versions
├── manifest.json                    # release manifest: versions, digests, signatures
├── bin/
│   └── dartrantime                  # the pinned AOT runtime, downloaded at install time
├── apps/  tools/  injections/  plugins/   # mirrors the source subprojects
├── config/                          # profiles/, policies.d/, config.yaml
├── state/                           # runtime state, see workspace-layout.md
└── logs/
```

The launcher resolves its own directory, so it works from anywhere:

```sh
#!/bin/sh
# alterione — generated by the installer. Runs the compiled release on the pinned runtime.
set -eu
home=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)
[ -n "${ALTERIONE_HOME:-}" ] && home="$ALTERIONE_HOME"
exec "$home/bin/dartrantime" "$home/alterione.aot" "$@"
```

Four rules make it safe:

1. **The runtime requirement is pinned to a major.minor range**, because the snapshot is.
   `alterione.yaml` carries `runtime.version: ">=3.13.0 <3.14.0"`, narrowed from the
   workspace's wide `>=3.13.0 <4.0.0` by the release tooling at build time. A runtime
   outside the range is a refusal with exit code `9`; it is never allowed to "probably
   work".
2. **The runtime is verified before it is used.** `bin/dartrantime` is checked against the
   SHA-256 in `manifest.json`, and the manifest against the release signature, on every
   install, update and launch. A digest mismatch never falls back to a system `dart` and
   never falls back to JIT — a JIT fallback would silently remove the tier-0 property
   this whole model rests on.
3. **The release closure is hook-free, and that is a gate.** Because
   `dart compile aot-snapshot` skips build hooks, CI parses the resolved dependency graph
   of `alteri_one_cli` and fails on any package shipping `hook/build.dart` or native
   assets. Adding one requires either a move to a self-contained executable for that
   target or an ADR — never a silent omission of the asset.
4. **`dart build cli` is not removed.** It remains the developer and SDK path and the
   fallback for any target whose closure is not hook-free. The two paths coexist, and
   which one produced a given artifact is recorded in `manifest.json`.

The install root mirrors the source subprojects so that a user reading
`~/.alterione/tools/fs/` is looking at the same kind of thing as `tools/fs/` in the
repository, and so that the deployed payload of every declared extension has exactly one
place to live and one digest record.

## Consequences

Easier: the runtime becomes a versioned, verifiable, replaceable dependency with its own
digest and its own constraint, stated in one file; the install footprint shrinks to the
part of the runtime an AOT snapshot needs; and a snapshot/runtime mismatch is a diagnosable
error at startup instead of a mysterious crash at first model turn.

Harder: one more downloaded artifact to verify and one more failure mode to test; the
hook-free closure is a real constraint on dependency selection that someone will
eventually resent; and the launcher script becomes a shipped, supported surface rather
than a build convenience.

Forbidden: executing `alterione.aot` on an unverified runtime; falling back to a system
`dart`, to JIT or to source execution when the runtime does not match; shipping a release
whose closure contains a build hook; naming the launcher anything but `alterione`.

## Alternatives considered

- **Keep the self-contained executable only.** Rejected: it welds the snapshot to its
  runtime, which is the one thing the release now needs to be able to vary, and it
  discards a runtime the user already has.
- **Ship the Dart SDK rather than a runtime.** Rejected: it is several times the size,
  and `pub`, `dart dev` and the full compiler are exactly the capabilities this product
  must not expose to a Tier 2 child.
- **Run the snapshot with a system `dart` found on `PATH`.** Rejected: silent version
  drift, no digest to verify, and an untrusted binary becomes the thing that executes the
  agent loop.
- **`dart compile exe` renamed to `alterione`.** Rejected: it cannot produce the split
  layout at all, and it does not run build hooks either, so it buys nothing.
- **JIT the sources at launch.** Rejected outright: it reintroduces runtime compilation
  and source shipping, and it makes every tier-0 and tier-1 claim in ADR-0003
  conditional.
