# 7. Dart 3.13: language rules

> Part of the AlteriOne specification, version 1.3. Reading map: `docs/spec/index.md`.

This section is the mandatory style guide. Write code by these rules and do not use outdated forms.

## 7.1 Class modifiers

| Modifier | When to use |
|---|---|
| `final class` | default for DTOs, value objects, domain entities, and events. Cannot be extended or implemented outside the library |
| `sealed class` | closed hierarchies: `AgentEvent`, extension messages. All subtypes live in the same library |
| `abstract interface class` | ports that external authors implement: `LlmPort`, `ModelProvider`, `Tool`. Cannot be extended; can be implemented |
| `abstract base class` | a base class that cannot be implemented outside its library but can be extended inside it |
| `mixin class` | not used without a specific reason |

The default is `final class`. Public ports are `abstract interface class`. Closed sets are `sealed`.

## 7.2 Primary constructors (stable in Dart 3.13)

Primary constructors were a preview in Dart 3.12 and are stable in Dart 3.13. Parameters are declared in the class header:

```dart
// A parameter with var or final creates a field. Without a modifier it is only a parameter.
final class Budget(
  final int maxSteps,
  final int maxTokens,
  final Duration maxDuration,
) {
  // Factory constructors are allowed alongside a primary constructor.
  factory Budget.standard() => Budget(12, 60_000, const Duration(seconds: 180));
}
```

Rules:
- **`var` and `final` on parameters of ordinary functions, methods, closures, and in-body constructors are compile errors in Dart 3.13.** These modifiers are reserved for declaring parameters of a primary constructor. Examples of errors: `void run(final int x)` and `Money(final int c) : cents = c`. Local variables and `for (final ...)` are not affected.
- `var` makes the field mutable. Use `final` by default and `var` only for state that really changes.
- A class with a primary constructor cannot have other non-redirecting generative constructors in its body. Additional constructors are `factory` or redirecting constructors.
- The body and initializers are added with `this`:

```dart
final class Point(var int x, var int y) {
  this : assert(x >= 0) {
    print('Point created at $x, $y');
  }
}
```

- Inside the body, `x` refers to the field created by the parameter.
- A mixin class can have a primary constructor only if it has no parameters, body, or initializers.
- Named primary constructors exist in the specification but are not used in this project. Use `factory` for named constructors.
- Classes generated by schemantic (section 10) do not use primary constructors: they are generated from `abstract class $Name`.
- Classes that use inheritance with explicit `super` arguments use classic constructors. Primary constructors are not combined with `extends` in this project.

Lint `use_declaring_parameters` encourages declaring parameters in the primary constructor. `unnecessary_primary_constructor_body` flags empty bodies.

## 7.3 `new` and `factory` in the class body (Dart 3.13)

Used only in classes **without** a primary header:

```dart
final class Point {
  final int x, y;
  new(this.x, this.y);          // equivalent to Point(this.x, this.y)
  new origin() : x = 0, y = 0;  // equivalent to Point.origin()
  factory Point.clone(Point other) => Point(other.x, other.y);
}
```

## 7.4 Private named parameters (Dart 3.12+)

Since Dart 3.12, a named parameter can initialize a private field directly:

```dart
final class Session {
  Session({required this._id, required this._userId});
  final String _id;
  final String _userId;
}
```

In a primary header with a private name: `class User({required var String _name});`.

## 7.5 Dot shorthands (Dart 3.10+)

The type name is omitted when the compiler knows the expected type from the context:

```dart
RunState state = .queued;
Widget w = Column(crossAxisAlignment: .start, mainAxisSize: .min, children: []);
switch (state) {
  case .running: ...
  case .completed: ...
}
```

Rules:
- Use dot shorthands where the type is obvious from the context: assignment with a declared type, a named argument, a `case` of an enum `switch`.
- Do not use them when the type is hard to infer or the reader cannot see it. Public API signatures state types explicitly.
- In record patterns and complex expressions, write the full name (`RunState.queued`).

## 7.6 Null-aware elements (Dart 3.8+)

```dart
final headers = [
  'content-type',
  ?authorization,      // added only when not null
];
final map = {
  'profile': profile,
  ?'session': sessionId,
};
```

## 7.7 Wildcard variables (Dart 3.7+)

`_` binds no value and can be repeated:

```dart
on FormatException catch (_) { ... }
final (_, second) = pair;
list.where((_) => true);
```

## 7.8 Records, patterns, switch expressions

Use them for composite results and exhaustive checks. For `sealed` hierarchies, a `switch` must be exhaustive and has no `default`.

```dart
(RunState, List<Effect>) step(Run run, RunEvent e) => ...;

final text = switch (event) {
  RunStarted(:final runId) => 'started $runId',
  RunFinished(:final state) => 'finished: ${state.name}',
  _ => 'other',
};
```

## 7.9 Extension types for typed identifiers

```dart
extension type RunId(String value) {}
extension type ApprovalId(String value) {}
extension type MemoryId(String value) {}
```

Extension types are erased at runtime: a `RunId` is a `String` when the program runs. `is RunId` checks do not work. Serialization is handled by DTO mapping at the API boundary.

## 7.10 Digit separators (Dart 3.6+)

`60_000`, `0x00_14_22`. Do not place `_` at the start or end of a number, or next to a decimal point or `e`.

## 7.11 Not used

- `dart:html`, `dart:js_util`, `package:js`, `dart:mirrors`.
- Augmentations: they are not listed among the features released in the SDK changelog for Dart 3.10–3.13. Do not rely on them.
- Macros: not released in the language.
- The Dart 3.13 additions `Isolate.runSync`, `Isolate.create`, and the event-loop control APIs are not used without a specific reason. Runtime extensions use `Isolate.spawnUri` (section 11).

## 7.12 analysis_options.yaml (excerpt)

```yaml
linter:
  rules:
    - no_dynamic_casts          # replaces the strict-casts option
    - no_raw_types              # replaces the strict-raw-types option
    - use_declaring_parameters
    - unnecessary_primary_constructor_body
    - unnecessary_type_name_in_constructor
    - prefer_initializing_formals
    - switch_on_type
    - discarded_futures
    - unawaited_futures
    - unnecessary_unawaited
    - async_return_with_no_await
    - initialize_in_field_declaration
analyzer:
  errors:
    missing_return: error
```

Do not enable `avoid_final_parameters` without verification: the lint may conflict with declaring parameters.

## 7.13 Build and format

- `dart format` (tall style is enabled for language version 3.7 and later). Before committing: `dart format --set-exit-if-changed .`.
- `dart analyze --fatal-infos` in CI.
- Binary: `dart build cli --target=alteri_one_bin/bin/alterione.dart` [VERIFY: exact output path and flags on your SDK version]. The alternative is `dart compile exe`.
- Dart 3.13.0 removed the built-in fallback root certificates. See section 18.4 for how to supply a CA file.
