# AGENTS.md: instructions for AI agents

This file is read first. It is short on purpose: it contains the invariants, the commands, and the reading map. Details are in `docs/spec/`. `AGENTS.md` files in subdirectories add local rules; they do not override this file.

## What the project is

AlteriOne is a personal universal assistant: one runtime with three modes (`chat`, `task`, `resident`), extensions (built-in or loaded as AOT modules), LLM providers, and LSP and MCP integrations in the MVP. It has a single owner and no multi-user mode. The stack is Dart 3.13 in a monorepo managed with the Dart workspace and Melos 7.

## Invariants (never break)

1. `runtime/core` must not import Flutter, clients, CLI, bin, or extensions. `tools/arch_check` enforces this.
2. Extensions get no access to core objects. They communicate only through serializable contracts and the host API.
3. Only `PolicyGate` decides whether a tool runs (`docs/spec/domain.md`). The model cannot bypass it, request permission directly, or choose an external server.
4. External content is untrusted. Taint labels apply to the whole run and to memory entries. Only the owner can clear a label.
5. The journal is written before any side effect. Run state is a projection of the journal (`domain.md`, `storage.md`).
6. Built-in tools of `llama-server` are disabled (`--tools`, `--agent`). `doctor` checks this.
7. The `final` and `var` modifiers on parameters are allowed only in a primary constructor header (Dart 3.13). They are forbidden everywhere else.
8. Configuration is YAML with a schema (JSON Schema generated by schemantic). Picoschema is not used. Secrets come only from `${env:NAME}`.
9. Generated files (`*.g.dart` and similar) are never edited by hand. Change the source and regenerate.
10. Public packages (`packages/`, `providers/`, `extensions/`) follow semver. A breaking change requires a new major version and a changelog entry.
11. Do not add multi-user mechanisms (accounts, tenants, cross-user permissions).
12. Forbidden and outdated patterns are listed in `docs/spec/forbidden-glossary.md`. Do not use them, even when copied from old examples.
13. All documentation and code comments are written in English.

## Commands

Before M0, `dart pub get` in the root is enough. After M0, the Melos scripts defined in the root `pubspec.yaml` (section `melos.scripts`) are available:
- `melos run format`: formatting;
- `melos run analyze`: analyzer with fatal infos;
- `melos run gen`: code generation;
- `melos run arch`: dependency rules;
- `melos run test`: tests;
- `melos run ci`: all of the above.

## Reading map

Before a task, open `docs/spec/index.md` and find the row for your task. Then read the `AGENTS.md` of the directory you work in. Read only the spec files you need; the rest waste context.

## How to work

- Plan first: which files you will change and which tests you will add. If the task touches several files, record the steps in `docs/plan/<milestone>.md` (template: `docs/plan/_template.md`).
- Do not silently invent decisions that are missing from the spec. Write the question to `docs/spec/open-questions.md` or ask the owner.
- Items marked [VERIFY] are not verified. First write a spike with a test, then the real code.
- Check dependency versions on pub.dev before `dart pub add`. Minimum versions are in `docs/spec/architecture.md`.
- Decisions are recorded as ADRs in `docs/adr/`. An accepted ADR is never edited. To reverse a decision, write a new ADR that supersedes the old one.
- Do not disable lint rules or tests to make the build green.

## Ask the owner before you

- change the public API of packages in `packages/`;
- add a dependency that is not in `docs/spec/architecture.md`;
- change PolicyGate, taint labels, run capabilities, or the host API;
- change an ADR or a spec section that describes an accepted decision;
- delete tests or golden files.

## Definition of done

- `melos run ci` is green;
- there are tests for the new behavior, including negative ones (refusal, error, boundary);
- `docs/spec/` is updated if the behavior is described there, and an ADR is written if a decision changed;
- steps in `docs/plan/` are checked off.
